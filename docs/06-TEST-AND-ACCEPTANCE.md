# OrderFlow acceptance

Planned verification uses synthetic records in an isolated local PostgreSQL cluster. Every state assertion comes from an authenticated read, a committed database invariant, a native observation, or a combination. Use separate connections and a deliberate synchronization point for races. Run tests after clean install, then repeat the critical native slice with a stopped Metro process before release.

| ID  | Workflow / check                                                                                                                                          | Required outcome                                                                                                                                       |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A01 | Bootstrap an empty business and site, invite two pickers and supervisor, exercise expired invite and revoked role.                                        | One-use bootstrap, scoped staff, no cross-site fields, no reuse after expiry and no removal of the last owner.                                         |
| A02 | Supervisor enters a verified synthetic two-line release. Retry identical then altered payload; try older revision and duplicate source order ID.          | Exactly one work item, two lines and one release audit fact. Same key reproduces the receipt and changed/stale inputs conflict.                        |
| A03 | Race two active picker sessions from separate connections. Restart API and database.                                                                      | One authorized winner, one scoped conflict, one claim/audit/receipt and the same winning assignee after restart.                                       |
| A04 | Pick part of the units. Try wrong SKU, repeated scan, excess quantity, stale version, other actor and open shortage.                                      | Progress persists. Illegal commands change neither committed quantities nor audit facts. After approved partial, exact eligible units can be sealed.   |
| A05 | Attempt early pack/handoff and then race cancel versus valid handoff at packed revision.                                                                  | Early commands denied. Exactly one legal transition wins. Handed-over units match the sealed contents.                                                 |
| A06 | Interrupt response after commit. Restart client, recover operation key and retry.                                                                         | Single durable result, stable ID/version, no double execution. A different payload or revoked actor cannot redeem the receipt.                         |
| A07 | Force-stop with saved offline pick draft. Resume first with valid ownership, then with claim revoked or updated by another picker.                        | Draft survives within scope. Reauthorization and fresh revision gate submission. Pack, handoff and cancellation cannot finalize offline.               |
| A08 | Two authorized actors compete for last returnable unit. Receive, inspect and disposition valid quantity.                                                  | One intake succeeds, audit is exact and pending inventory/refund remains independently disclosed.                                                      |
| A09 | Try anonymous, foreign business/site, wrong role, direct-link and improper field access on queue, work and commands.                                      | No protected rows/fields, writes or minted receipts. Export and subscriptions have no routes in the first slice.                                       |
| A10 | Seed 1,000 synthetic jobs and exercise cursor, scope, filters, stale snapshots and rate/body caps.                                                        | Stable ordering, no cross-scope replay, bounded results. Restart/expiry recovery returns page one. Collect timing separately.                          |
| A11 | Migrate clean and prior schema, restore a dedicated local backup and compare membership, work, claims, receipts and audit.                                | Stable identifiers and counts, known recovery time and rollback safeguards.                                                                            |
| A12 | Verify actual Android/iOS native build, check camera denial/manual fallback, permission and manifest boundaries, lock/cleanup, accessibility and upgrade. | Device-specific evidence with build versions and artifact SHA-256. Missing physical/iOS results retain the corresponding gate.                         |
| A13 | Future owner integration only. Release authoritative order, invoke inventory effects with concurrent retries and reconcile from a receipt.                | One stock posting across actual owner services, verified source mappings and no refund side effects. Blocked until authority and cutover are approved. |

Use Jest and React Native Testing Library for native interaction behavior, TypeScript strict checks, model/locale validation, real PostgreSQL integration tests, and a free native acceptance runner or recorded device workflow. Track line, statement, branch and function coverage individually where supported with 90% overall targets and 95% for critical auth/warehouse state logic, plus 90% changed-code coverage where measurable. Perform dependency audit, license inventory and secret scans after a lockfile exists. Record scanner controls and exclusions.
